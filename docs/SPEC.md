## 1. 추적성 규칙

요구사항은 3단계로 추적한다.

```
UR (사용자 요구사항, 원문)  →  REQ (사양 요구사항)  →  코드 [REQ-xxx] 태그
                                         └──────────→  TC (테스트 케이스, TEST.md)  →  테스트 코드 `TC-xxx` 함수명
```

- **UR**: 사용자가 말한 요구사항 원문. 아래 2장 표에서 REQ 로 분해한다.
- **REQ**: 검증 가능한 단위로 쪼갠 사양. ID 형식 `REQ-<영역>-<3자리>`.
- **코드**: 구현 위치의 주석에 `[REQ-xxx]` 를 단다 (`app/src/main`, `firestore.rules`).
- **TC**: [TEST.md](TEST.md) 에 정의. ID 형식 `TC-<영역>-<REQ번호>-<2자리>`. 자동화된 TC 는 테스트 함수명에 TC ID 를 포함한다.
- `python3 tools/trace_check.py` 가 위 연결을 검사하고 [TRACEABILITY.md](TRACEABILITY.md) 를 다시 만든다. 누락이 있으면 실패(exit 1)한다.
- 요구사항을 추가/변경하면 **SPEC → 코드 태그 → TEST.md → 테스트 코드** 순으로 갱신하고 스크립트를 실행한다.

## 4. 기능 요구사항

### 4.1 문자 자동 기입 (SMS)

#### REQ-SMS-001 카드 승인 문자 실시간 자동 기입
- 문자를 수신하면 앱이 실행 중이 아니어도 내용을 해석하여 카드 승인/취소 문자이면 **현재 가계부**(REQ-SHARE-008)에 거래로 저장한다.
- 여러 조각으로 온 장문 문자는 발신번호별로 합쳐서 해석한다.
- 로그인하지 않았거나 가계부가 없으면 기입하지 않는다(이후 REQ-SMS-005 로 복구 가능).
- 문자 원문은 저장하지 않는다(개인정보 최소화). 해석 결과만 저장한다.

#### REQ-SMS-002 카드사 문자 해석
- 대상 카드사: 신한, 삼성, KB국민, 현대, 롯데, 하나, 우리, NH농협, BC, IBK기업, 씨티 등 (`카드` 또는 `체크` 표기).
- 추출 항목: 카드명(+끝 4자리가 있으면 포함), 결제 금액, 승인 일시(월/일 시:분), 가맹점명, 할부 개월(일시불=0).
- 문자에 연도가 없으므로 수신 시각의 연도를 쓰되, 결과가 수신 시각보다 하루 이상 미래이면 전년도로 본다(연말·연초 경계).
- `[Web발신]` 머리말은 무시한다. 단문(한 줄) / 장문(여러 줄) 형식 모두 지원한다.
- 가맹점명을 찾지 못하면 `미확인 가맹점` 으로 기입한다.

#### REQ-SMS-003 승인 취소 처리
- 본문에 `취소` 가 있으면 취소(환불) 거래(`type=CANCEL`)로 기입한다.
- 취소 거래는 월 합계와 항목별 합계에서 차감한다. 항목 합계가 0 이하이면 그래프에서 제외한다.
- 리스트에서는 `취소 +금액` 으로 구분해 표시한다.

#### REQ-SMS-004 카드 승인 문자가 아닌 문자 제외
- 카드사명, `승인`/`취소`, 금액(원), 일시가 모두 있어야 카드 문자로 본다.
- `거절`(승인 거절), `(광고)`, `결제예정`, `청구` 가 포함된 문자는 제외한다.
- `누적`, `잔액`, `한도`, `사용가능` 금액은 결제 금액으로 인식하지 않는다.

#### REQ-SMS-005 문자함 가져오기
- 내역 화면의 "문자함에서 가져오기" 로 **선택한 월**에 수신된 문자함 문자를 해석해 기입한다.
- 결과로 확인한 문자 수 / 추가 건수 / 중복 건수를 알려준다.

#### REQ-SMS-006 중복 기입 방지
- 해석 결과(카드명, 금액, 일시(분 단위), 가맹점, 취소 여부)로 결정적 거래 ID 를 만든다. 실시간 수신과 문자함 가져오기에서 같은 문자는 같은 ID 가 된다.
- 같은 ID 의 거래가 이미 있으면 새로 저장하지 않는다(수동으로 고친 내용이 덮어쓰이지 않는다).
- 삭제는 soft delete(`deleted=true`)로 하여, 삭제한 문자 내역이 문자함 가져오기로 되살아나지 않게 한다.
- 제약: 같은 카드·같은 가맹점·같은 분·같은 금액의 실제 결제가 두 번 있으면 한 건으로 합쳐진다. 이 경우 사용자가 수동 추가(REQ-LIST-004)로 보정한다.

#### REQ-SMS-007 항목 자동 분류
- 가맹점명 키워드로 항목을 정한다. 항목: 식비, 카페/간식, 교통, 쇼핑, 생활/마트, 의료/건강, 문화/여가, 통신/공과금, 교육, 기타.
- 어느 키워드에도 맞지 않으면 `기타`.
- 영문 키워드는 단어 경계로 비교한다 (예: `KTX` 는 교통이며 통신사 `KT` 로 분류하지 않는다).
- 분류 우선순위: 카페 → 식비 → 교통 → 의료 → 문화 → 교육 → 생활 → 쇼핑 → 통신 (예: `쿠팡이츠` 는 식비).

#### REQ-SMS-008 문자 권한
- 로그인 후 메인 화면에서 `RECEIVE_SMS`, `READ_SMS` 권한을 요청한다.
- 거부 시 상단에 안내 배너와 "허용" 버튼을 보여주고, 문자함 가져오기를 누르면 권한을 다시 요청한다. 권한이 없어도 수동 입력·조회·공유 기능은 동작한다.
- 참고: Google Play 배포 시 SMS 권한은 정책 심사(Permissions Declaration) 대상이다.

### 4.2 월별 도넛 그래프 (CHART)

#### REQ-CHART-001 월별 항목별 지출 도넛 그래프
- 통계 탭에 선택한 월의 거래만으로 항목별 순지출(지출−취소)을 도넛 그래프로 표시한다.
- 각 조각의 크기는 항목 비율, 색상은 항목별 고정 색이다. 내역이 없으면 빈 회색 링을 그린다.

#### REQ-CHART-002 월 이동
- 이전/다음 버튼으로 월을 바꾼다. 기본값은 이번 달. 통계·내역 탭이 같은 월을 공유한다.

#### REQ-CHART-003 범례, 비율, 총액
- 도넛 가운데에 월 총지출, 아래에 항목별 색·이름·비율(소수 1자리 %)·금액을 금액 내림차순으로 표시한다.
- 금액은 천 단위 쉼표와 `원` 으로 표기한다 (예: `12,500원`).

### 4.3 내역 리스트 / 수정 (LIST)

#### REQ-LIST-001 월별 내역 리스트
- 내역 탭에 선택한 월의 거래를 최신순으로 보여준다. 각 행: 항목 색, 사용처, 일시(MM/dd HH:mm), 항목, 카드명, 할부, 수동/수정됨 표시, 메모, 금액.
- 상단에 건수와 순합계를 표시한다.

#### REQ-LIST-002 내역 수정
- 행을 누르면 수정 창에서 금액, 사용처, 항목, 일시, 메모, 구분(지출/취소)을 바꿀 수 있다.
- 문자로 기입된 거래를 고치면 `수정됨` 으로 표시한다(`manuallyEdited=true`).

#### REQ-LIST-003 내역 삭제
- 수정 창에서 확인 후 삭제한다. 삭제는 공유된 구성원 모두에게 반영된다.

#### REQ-LIST-004 수동 내역 추가
- 내역 탭의 + 버튼으로 현금 결제 등 문자로 오지 않은 내역을 추가한다(`source=MANUAL`).

#### REQ-LIST-005 입력 검증
- 금액: 숫자(쉼표 허용), 1원 이상 10억 원 이하.
- 사용처: 공백 불가, 50자 이하. 메모: 200자 이하.
- 일시: `yyyy-MM-dd HH:mm` 형식.
- 검증에 실패하면 저장하지 않고 오류 문구를 수정 창에 보여준다.

### 4.4 공유 / 로그인 (SHARE)

#### REQ-SHARE-001 구글 계정 로그인
- 로그인하지 않으면 로그인 화면만 보여준다. "Google 계정으로 로그인" 으로 Firebase 인증을 한다.
- 로그인 상태는 앱을 다시 실행해도 유지된다.

#### REQ-SHARE-002 로그아웃
- 공유 탭에서 로그아웃하면 로그인 화면으로 돌아가고, 저장된 현재 가계부 선택을 지워 이후 문자가 기입되지 않는다.

#### REQ-SHARE-003 가계부 생성
- 최초 로그인 시 서버에 내 가계부가 하나도 없으면 `내 가계부` 를 자동으로 만든다(오프라인이면 건너뛰고 다음 실행 때 다시 시도).
- 공유 탭에서 이름을 입력해 새 가계부를 만들 수 있다. 만든 사람이 소유자가 된다.

#### REQ-SHARE-004 초대 코드 발급/공유
- 가계부를 만들 때 6자리 초대 코드를 발급한다. 문자 집합은 `0 O 1 I` 를 뺀 영문 대문자+숫자 32자.
- 공유 탭에서 코드를 보여주고 "보내기" 로 메신저 등에 공유한다.
- 초대 코드는 코드를 아는 사람만 조회할 수 있다(목록 조회 불가).

#### REQ-SHARE-005 초대 코드로 참여
- 공유 탭에서 코드를 입력하면 해당 가계부 구성원이 된다. 입력은 대소문자·공백·하이픈을 무시한다.
- 형식이 틀리거나 없는 코드이면 오류를 알린다.

#### REQ-SHARE-006 구성원 간 실시간 동기화
- 같은 가계부의 구성원은 같은 데이터를 보며, 한 사람이 추가·수정·삭제하거나 문자로 자동 기입된 내역이 다른 구성원 화면에 실시간 반영된다.
- 공유 탭에 구성원 목록(이름, 만든 사람 표시)을 보여준다.

#### REQ-SHARE-007 접근 제어
- 가계부와 거래는 구성원만 읽고 쓸 수 있다(Firestore 보안 규칙 `firestore.rules`).
- 소유자와 초대 코드는 바꿀 수 없다. 구성원 목록은 소유자만 바꾸며, 비구성원은 유효한 초대 코드로 자기 자신만 추가할 수 있다.

#### REQ-SHARE-008 현재 가계부 선택
- 여러 가계부에 속한 경우 상단 제목을 눌러 현재 가계부를 고른다. 선택은 저장되며, 문자 자동 기입 대상이 된다.
- 선택한 가계부가 목록에 없으면 첫 번째 가계부를 쓴다.

## 5. 비기능 요구사항 / 제약

- 오프라인에서도 조회·수동 입력이 되고, 온라인이 되면 동기화된다(Firestore 오프라인 캐시).
- 실시간 수신 처리는 BroadcastReceiver 제한 시간(약 10초) 안에 끝나도록 8초 제한을 둔다. 놓친 문자는 REQ-SMS-005 로 복구한다.
- 빌드 전 Firebase 프로젝트에서 `app/google-services.json` 을 받아 넣고, Authentication 에서 Google 로그인을 켜고, 앱 SHA-1 을 등록하고, `firestore.rules` 를 배포해야 한다 (README 참고).

## 6. 범위 밖 (향후 검토)

- 수입 내역, 예산 설정, 항목별 상세 필터
- 사용자가 고친 항목을 가맹점별로 학습하는 분류
- 가계부 나가기 / 구성원 내보내기 UI
- 카드 알림앱 푸시(카카오톡 알림톡 등) 해석
